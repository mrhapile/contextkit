# Document

Capture the result so the next person can use it quickly.

## Use when

- Capture the result so the next person can use it quickly.

## Do

- Explain the outcome in plain language.
- Include the commands, paths, or decisions someone will need later.
- Keep the writing short but actionable.

## Avoid

- Repeating implementation details that the reader does not need.
- Writing documentation that does not help future use.
